# Реестр требований-по-наблюдению

> Требований нет, поэтому базовая линия строится из документации Medusa v2 и наблюдаемого поведения.
> Формат: ожидание + основание (док / наблюдение / согласованность) + статус подтверждения.

Статусы: `подтверждено` / `нарушено (кандидат)` / `наблюдение` / `спланировано`.

| ID | Ожидание (как должно быть) | Основание | Статус |
|----|----------------------------|-----------|--------|
| R-001 | Списковые эндпоинты возвращают `count` = общее число записей по фильтру, независимо от `limit`/`offset` | Док Medusa v2 (pagination); внутренний эталон: Admin API | нарушено (подтверждено): BUG-001 (TC-001) |
| R-002 | Отрицательные/нечисловые `limit`, `offset` отклоняются как 4xx (`invalid_data`) с понятным сообщением | HTTP-семантика; формат ошибок Medusa v2 | нарушено (подтверждено): BUG-002 (TC-002) |
| R-003 | Валюта цен определяется регионом: Europe (eur) → отображение в EUR | Док (регион → currency_code); API `currency_code: eur` | подтверждено: `€10.00` на витрине (заметка о `$` снята) |
| R-004 | `/robots.txt` и `/sitemap.xml` отдаются как соответствующие ресурсы (или 404), а не HTML-страница витрины | Веб-конвенции/SEO | нарушено (подтверждено): BUG-019 (TC-003/TC-031) — soft-200 HTML для `/.env`, `/.gitignore`, `/package.json` и др. |
| R-005 | Несуществующие маршруты → 404 | HTTP-семантика; эталон — админка (корректная 404) | частично: `/dk/*` — ок; корневые несуществующие «файловые» пути (`/.env`, `/robots.txt`, `/sitemap.xml`, `/openapi.json`) отдают 200 HTML — нарушено (подтверждено): BUG-019 (TC-031) |
| R-006 | Прод-метаданные страниц не ссылаются на localhost | Наблюдение `og:image`/`twitter:image` | нарушено (кандидат): `http://127.0.0.1:8000/...` (TC-004) |
| R-007 | Ответы содержат базовые заголовки безопасности (HSTS, CSP, X-Frame-Options, X-Content-Type-Options) | Security baseline | нарушено (подтверждено): BUG-013 (TC-005); следствие — кликджекинг (TC-030) |
| R-008 | Store API требует `x-publishable-api-key`; клиентские операции — аутентификацию покупателя | Док + наблюдение | подтверждено: без ключа/токена → 401/400 |
| R-009 | Admin API требует Bearer JWT | Док + наблюдение | подтверждено: `/admin/products` без токена → 401 |
| R-010 | Чек-аут: `POST /store/carts/{id}/complete` → `{type:"order"}`; при ошибке `{type:"cart", cart, error}` (HTTP 200) | Док Medusa v2 | спланировано (TC-006) |
| R-011 | Страница подтверждения заказа проверяет существование заказа | Наблюдение: `/dk/order/123/confirmed` → 200 | требует UI-проверки (TC-007) |
| R-012 | Store и Admin показывают согласованные данные (товары, цены, заказы, инвентарь) | Внутренняя согласованность | частично: расхождение `count` (TC-001/BUG-001); дифф по остальному — TC-008 подтверждён |
| R-013 | Невалидное значение `order` (пустое, несуществующее поле) отклоняется 4xx | Формат ошибок Medusa v2; HTTP-семантика | нарушено (подтверждено): BUG-003 (TC-015) |
| R-014 | Невалидные date-фильтры (`updated_at`/`created_at`: пусто, не-дата) отклоняются 4xx | Формат ошибок Medusa v2; HTTP-семантика | нарушено (подтверждено): BUG-004 (TC-016) |
| R-015 | Продовая UI-сборка не обращается к localhost/dev-портам | Наблюдение (127.0.0.1:8000 в og:image; 127.0.0.1:9001 в запросе опций) | нарушено (подтверждено): BUG-005 (TC-018), связанный TC-004 |
| R-016 | Несуществующий ресурс отдаёт 4xx-статус (не 200) | HTTP-семантика; эталон — `/dk/nonexistent` (404) | нарушено (подтверждено): BUG-006 (TC-019) |
| R-017 | `<title>` страниц уникален и не дублирует суффикс бренда | SEO-конвенции; эталон — карточка товара | нарушено (подтверждено): BUG-007 (TC-020) |
| R-018 | Списки выбора в UI не содержат дублирующихся значений | UX-конвенции | нарушено (подтверждено): BUG-008 (TC-021) |
| R-019 | `POST /store/shipping-options/{id}/calculate` с валидным `cart_id` отвечает 2xx/4xx, а не 5xx | Спека v2.21 (PostShippingOptionsIdCalculate) | нарушено (подтверждено): BUG-009 (TC-025) |
| R-020 | Admin API: невалидные значения (диапазоны, пустые строки, неверные типы, отсутствующие обязательные поля) → 4xx | Формат ошибок Medusa v2; эталон — остальные admin-эндпоинты | нарушено (подтверждено): BUG-010 (TC-026) |
| R-021 | Регион создаётся только с существующей валютой | Целостность данных; список валют системы | нарушено (подтверждено): BUG-011 (TC-027) |
| R-022 | Все ссылки UI ведут на существующие страницы | UX-конвенции | нарушено (подтверждено): BUG-012 (TC-028) |
| R-023 | Страницы не встраиваются в чужой iframe (XFO/CSP frame-ancestors) | Security baseline | нарушено (подтверждено): BUG-013 (TC-030) |
| R-024 | Элементы форм имеют программно-связанную метку (label/aria-label/aria-labelledby) | WCAG 2.2 (3.3.2/4.1.2) | нарушено (подтверждено): BUG-014 (TC-032) |
| R-025 | Интерактивные элементы (кнопки) имеют доступное имя | WCAG 2.2 (4.1.2) | нарушено (подтверждено): BUG-015 (TC-033) |
| R-026 | Изображения имеют `alt`, `role="img"` имеет имя | WCAG 2.2 (1.1.1) | нарушено (подтверждено): BUG-016 (TC-034) |
| R-027 | Контраст текста соответствует WCAG AA | WCAG 2.2 (1.4.3) | нарушено (подтверждено): BUG-017 (TC-035) |
| R-028 | Ссылки имеют различимый текст; интерактив не вложен | WCAG 2.2 (2.4.4/4.1.2) | нарушено (подтверждено): BUG-018 (TC-036) |
| R-029 | Токены изолированы: customer JWT не действует в Admin API, подделка отвергается | Док + границы безопасности | подтверждено: `tests/nfr/auth.spec.ts` (TC-037) |
| R-030 | HTTP перенаправляется на HTTPS (порт 80 обслуживается) | Security baseline | наблюдение: `http://<host>` → socket hang up (TC-039) |
| R-031 | Производительность/стабильность: согласованное время ответов без 5xx/таймаутов | Наблюдаемая согласованность (требований нет) | подтверждено (baseline): медианы 94–409 мс, 0 ошибок (TC-038) |
