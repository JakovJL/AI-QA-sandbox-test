## Предусловия

- Доступен Store API с валидным `x-publishable-api-key`.
- В системе 4 товара (проверено: `/admin/products?limit=1` → `count: 4`).

## Шаги воспроизведения

1. `GET /store/products?limit=1` — ожидаем `count = 4`.
2. `GET /store/products?limit=2`, `?limit=3`, `?limit=0`, `?limit=1&offset=1`, `?limit=1&offset=100` — ожидаем `count = 4` в каждом.
3. Для сравнения: `GET /admin/products?limit=1` и `GET /store/product-categories?limit=1` — оба дают корректный `count = 4`.

## Ожидаемый результат

`count` — общее количество записей, соответствующих фильтру, независимо от `limit`/`offset`.
Основание: официальная спека Medusa v2 (`vendor/openapi/store.openapi.full.yaml`, схема `StoreProductListResponse`:
«count … The total count of items»); внутренний эталон — Admin API и `/store/product-categories`.

## Фактический результат

`count` равен количеству записей на странице:

| Запрос | returned | count | ожидалось |
|---|---|---|---|
| `/store/products?limit=1` | 1 | 1 | 4 |
| `/store/products?limit=2` | 2 | 2 | 4 |
| `/store/products?limit=3` | 3 | 3 | 4 |
| `/store/products?limit=0` | 0 | 0 | 4 |
| `/store/products?limit=1&offset=1` | 1 | 1 | 4 |
| `/store/products?limit=1&offset=100` | 0 | 0 | 4 |

## Артефакты

- Проверки: `tests/api/store-products-count.spec.ts` (6 падений — репродьюсеры; контроли проходят).
- Сырые ответы: `reports/artifacts/store-products-count/*.json` (url, returned, count, adminTotal).
- Контрактный прогон: `tests/api/store-contracts.spec.ts` + артефакты `reports/artifacts/store-contracts/`.

## Примечания

- Изолировано на `/store/products`: `/admin/products` и `/store/product-categories` возвращают корректный `count`.
- Следствие для потребителей: витрина/клиенты не могут вычислить общее число страниц и «показать ещё» — хвост каталога теряется.
- Дефект воспроизводится и при `offset` за пределами данных (count=0 вместо 4) — значит, дело не в подсчёте возвращённых строк на клиенте, а в серверном формировании `count`.
