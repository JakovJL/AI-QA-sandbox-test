## Предусловия

- Доступен Store API с валидным `x-publishable-api-key`.

## Шаги воспроизведения

1. `GET /store/product-categories?updated_at=` (пустое значение).
2. `GET /store/product-categories?updated_at=not-a-date`.
3. `GET /store/product-categories?created_at=`.
4. `GET /store/collections?updated_at=`, `GET /store/product-options?updated_at=`.
5. Контроль: `GET /store/product-categories?updated_at=2026-09-24` — валидная дата.

## Ожидаемый результат

Невалидная дата → 4xx `invalid_data` с понятным сообщением.
Основание: семантика ошибок Medusa v2; принцип «пользовательский ввод не приводит к 5xx».

## Фактический результат

- `updated_at=` / `updated_at=not-a-date` / `created_at=` → **HTTP 500** `unknown_error`
  на `/store/product-categories`, `/store/collections`, `/store/product-options` (5/5).
- Контроль: `updated_at=2026-09-24` → 200.

## Артефакты

- Проверки: `tests/api/store-input-validation.spec.ts` (кейсы `invalid-date-filter`, 5 падений-репродьюсеров).
- Артефакты ответов: `reports/artifacts/store-input-validation/invalid-date-filter-*.json`.
- Фаззинг: `reports/artifacts/schemathesis/run.log`, `summary.md`.

## Примечания

- Тот же класс, что BUG-002 и BUG-003: отсутствие валидации значений query-параметров → 500.
- В фаззинге также встречался смешанный кейс `?updated_at=` на `/store/collections` — тот же триггер.
