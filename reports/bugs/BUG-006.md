## Предусловия

- Открытая витрина.

## Шаги воспроизведения

1. Открыть `/dk/order/order_fake_123/confirmed` (несуществующий id).
2. Подождать ~4 сек и сравнить с честным 404: `/dk/nonexistent-route-xyz`.

## Ожидаемый результат

Для несуществующего заказа — HTTP 404 (как у неизвестного маршрута) и нейтральный title.

## Фактический результат

- HTTP **200**, в теле — «Page not found / The page you tried to access does not exist. / Go to frontpage»,
  при этом `<title>` = **«Order Confirmed»** (противоречит содержимому).
- `/dk/nonexistent-route-xyz` ведёт себя корректно: HTTP 404, title «404».

## Артефакты

- Проверка: `tests/ui/storefront.spec.ts` → `UI-2` (падает-репродьюсер).
- Улики: `reports/artifacts/ui-storefront/ui-2-evidence.json` (status 200, title, showsPageNotFound), скриншот `ui-2-order-fake.png`.

## Примечания

- Механика: серверная часть Next.js уже отправляет 200 (стриминг), а `notFound()` отображается позже — пользователь видит
  корректный текст, поисковики/клиенты — «успешную» страницу с ложным title.
- Для валидного заказа страница работает корректно (проверено живым заказом `order_01M3KPSPKBY4W3694XFA3S1P6F`).
