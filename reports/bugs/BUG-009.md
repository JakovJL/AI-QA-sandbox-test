## Предусловия

- Корзина с товаром (1× Sweatshirt), в регионе Europe.

## Шаги воспроизведения

1. `GET /store/shipping-options?cart_id=<cart>` — получить опции (Standard/Express).
2. `POST /store/shipping-options/{option_id}/calculate` с телом `{"cart_id":"<cart>"}` (по спеке обязателен только `cart_id`).
3. Повторить для обеих опций; также с `{"cart_id":"<cart>","data":{}}`.

## Ожидаемый результат

200 с рассчитанной ценой (или 4xx, если расчёт неприменим для `flat`-опции). Основание: спека v2.21
(`PostShippingOptionsIdCalculate`: тело требует только `cart_id`; «If the fulfillment provider fails to calculate the price, this route returns an error»).

## Фактический результат

HTTP **500** `{"code":"unknown_error","type":"unknown_error","message":"An unknown error occurred."}` — 6/6 (обе опции, с `data` и без).
Пустое тело даёт корректный 400 (`Field 'cart_id' is required`), т.е. валидация входа есть, но обработка валидного запроса падает.

## Артефакты

- Проверка: `tests/api/shipping-calculate.spec.ts` (падает-репродьюсер).
- Артефакты: `reports/artifacts/store-shipping-calculate/calculate-attempts.json`.

## Примечания

- Обе опции имеют `price_type: flat`; по спеке маршрут предназначен для `calculated`. Возможен апстрим-кейс
  «manual-провайдер не умеет считать», но ответ 500 `unknown_error` на документированный валидный запрос — дефект обработки.
- UI витрины этот маршрут не использует (берёт `amount` из списка), поэтому пользовательский эффект ограничен.
