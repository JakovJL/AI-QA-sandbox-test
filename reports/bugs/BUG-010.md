## Предусловия

- Валидный admin-токен.

## Шаги воспроизведения

Списочные (GET):
1. `/admin/products?offset=-1`, `?limit=-1`, `?order=`, `?created_at=`
2. `/admin/orders?offset=-1`, `/admin/customers?limit=-1`, `/admin/inventory-items?offset=-1`

Формы (POST):
3. `POST /admin/stock-locations` с телом `{}` (спека требует только `name` → ожидаем 400).
4. `POST /admin/stock-locations/{id}` с телом `{"name":123}`.
5. `POST /admin/regions` с телом `{"name":"...","currency_code":""}`.

## Ожидаемый результат

4xx `invalid_data` с понятным сообщением (как это делают остальные admin-эндпоинты: products/promotions/regions/sales-channels и т.д. на `{}` отвечают 400).

## Фактический результат

Все 11 запросов → HTTP **500** `{"code":"unknown_error","type":"unknown_error","message":"An unknown error occurred."}`.

## Артефакты

- Проверка: `tests/api/admin-input-validation.spec.ts` (11 падений-репродьюсеров).
- Артефакты: `reports/artifacts/admin-input-validation/*.json`.

## Примечания

- Тот же класс, что BUG-002/003/004 (Store), но на стороне Admin API: тип значения иногда проверяется
  (например, `POST /store/carts {region_id:123}` → 400), а диапазоны/пустые строки — нет.
- Проверка 400 на «пустое тело» у 15 admin-эндпоинтов показала: 14 отвечают корректно, падает только `stock-locations`.
