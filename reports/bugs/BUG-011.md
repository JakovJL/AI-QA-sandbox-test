# BUG-011: Admin API: регион создаётся с несуществующей валютой (200 + сохранение невалидных данных)

| Поле | Значение |
|------|----------|
| ID | BUG-011 |
| Область | Регионы/валюты (риск 4); валидация данных (риск 10) |
| Severity | Medium |
| Priority | P3 |
| Слой | API |
| Окружение | `sandbox-session-cand-c26fa443df2a4d52ba4c0f61ea385fac.fly.dev`, 28.09.2026; найден при углублённом поиске |
| Воспроизводимость | всегда |
| Статус | Confirmed (внесён в реестр 28.09.2026) |
| GitHub Issue | [#11](https://github.com/JakovJL/AI-QA-sandbox-test/issues/11) |

## Предусловия

- Валидный admin-токен.

## Шаги воспроизведения

1. `POST /admin/regions` с телом `{"name":"QA Invalid Currency","currency_code":"zzz"}`.
2. Проверить ответ и список регионов.

## Ожидаемый результат

4xx `invalid_data` — валюта должна существовать (в системе 126 ISO-валют, `zzz` не входит; регион с такой валютой ломает расчёты цен).

## Фактический результат

HTTP **200**, регион создан с `currency_code: "zzz"` и сохранён в системе
(исправлено вручную: DELETE региона 200). При этом `currency_code: ""` → 500 (см. BUG-010).

## Артефакты

- Проверка: `tests/api/admin-input-validation.spec.ts` → тест «admin region: nonexistent currency code is rejected» (падает-репродьюсер; при 200 тест сам удаляет созданный регион).
- Артефакты: `reports/artifacts/admin-input-validation/region-invalid-currency*.json`.

## Примечания

- Диапазон: допустимыми считаются только коды из store currencies; `zzz` не входит.
- Опасность: невалидная валюта региона приведёт к ошибкам/некорректным ценам при использовании региона.
