## Наблюдения вне дефектов

- TC-013: required-поля Store-схем (`status`, `external_id`, `deleted_at`, timestamps, country `id`) не совпадают со спекой;
  required-списки идентичны в спеках v2.15.0/v2.18.0/v2.21.1, Store и Admin согласованы для currencies/стран — вероятна неточность спеки.
- 401-ответы документированы как `text/plain`, фактически `application/json` (фаззинг, 9 операций) — тот же класс расхождения спеки.
- `limit=1.5` принимается (200); `q=`, `fields=`, `with_deleted` — безопасны; неизвестный `category_id` игнорируется (200/пусто).
- Store API не отдаёт `variants.sku` (поле не входит в разрешённые — отбрасывается молча, по спеке так и должно быть).
- Артефакт песочницы `/blocking-fault.js` — приманка, не дефект.

## Вердикт

API-слой рабочий по happy-path: корзина/чекаут (включая идемпотентность, резервы инвентаря и границы количеств)
и согласованность Store↔Admin подтверждены. Основной риск — обработка невалидного ввода: три семейства параметров
(`limit`/`offset`, `order`, date-фильтры) дают 500 вместо 400 (BUG-002/003/004), плюс сломанный `count` пагинации (BUG-001).

Дальше: этап 3 (UI) — витрина и админка в контуре А (agent-browser/Chrome) + перенос находок в контур Б;
кандидаты — страница подтверждения заказа, отсутствие поиска vs стоковый starter, состояния ошибок.
